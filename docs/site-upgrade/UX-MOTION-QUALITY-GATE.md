# Andy 开源网站 UX 与动效质量门禁（2026-11-24）

> 唯一交付账本依然是 [PLAN.md](./PLAN.md)。本文件定义可复现的用户体验验收要求，不替代线上实测、GPT 复审、人工设备或 PDF 视觉签收。

## 判断原则：复杂度必须留在系统里

| 原则 | 失败信号 | 可验收的改造 |
|---|---|---|
| 系统能判断的不留给用户 | 表单要求重复填写已知信息、需要手算 | 合法推断默认项，展示推断依据及可修改入口 |
| 此刻没用的就不出现 | 首屏几十个选项、连续卡片噪音 | 按任务阶段渐进展示；不阻断深层教程访问 |
| 能替人做的直接做 | 用户重复复制、手动导出格式 | 一键生成可编辑草稿与检查清单；不可逆对外动作仍由人确认 |
| 同一件事处处一样 | 同类按钮有不同文案/颜色/动作 | 一套动作名称、状态、语义颜色及可复用组件 |
| 按下有回应，再按能收回 | 点击无反馈；没有撤销与状态回显 | 成功/失败/处理中区分，安全可逆动作提供撤销 |
| 不打断手上的事 | 勾选导致页面刷新、输入丢失、视图跳动 | 保留焦点、光标、滚动和未提交输入；后台刷新不夺焦点 |
| 常用易做，丢东西难误碰 | 删除与保存同权重，误操作不可恢复 | 常用操作显眼；删除、覆盖、发布前显示影响/确认与备份路径 |
| 界面自己说明自己 | 专业术语堆叠、按钮需要教程解释 | 控件文案说清行为和后果；错误提示说明下一步 |

## 动效规范：按状态变化审查，不按组件凑动画

- **状态库存**：出现、消失、焦点移动、列表过滤、切换视图、加载、保存成功、复制、失败、撤销、删除、完成、数值改变。
- **解释变化而非装饰**：过渡只用于说明来源/去向及状态联系。重复录入、打字、勾选不触发全屏动画。
- **单一节奏**：微交互参考 110–140ms；视图过渡参考 160–220ms；同类变化使用同一缓动曲线。具体值须结合实机测试调整，非硬套“苹果参数”。
- **可打断**：导航切换中再次操作应取消上一次过渡后自然衔接；拖拽反馈直接跟手。
- **性能**：只动 transform / opacity 优先；不因动画改变布局或造成长列表掉帧。真实帧时间、CLS、INP 等需测量并保存记录，未测不得声明“满帧”。
- **跨环境**：360/390px 手机、1280px 桌面、窄宽窗口、深色/浅色、键盘及触控；`prefers-reduced-motion: reduce` 下取消非必要动画。
- **质量边界**：页面/组件仍须满足 WCAG 可见焦点、状态公告、点击目标、对比度；无横向溢出、抖动、闪烁与不可理解的数值跳变。

## 发布和复审门禁

1. **记录具体用户任务和失败原因**：尽可能有代码定位、屏幕截图或可复现浏览器步骤，避免空泛“设计差”。
2. **最小改动方案**：从源文件修改，不重排未回归的原工具；先处理 P0 操作错误和数据丢失，再做动效统一。
3. **功能检查**：实际点击/输入/修改/撤销/导出；保留用户输入，回归原有安全阻断、隐私、下载。
4. **视觉与动效**：浏览器断言视口、深浅色、reduced motion、焦点恢复、无溢出；截图人工复核。若声称顺滑需保存实际性能测量。
5. **咨询复核**：Gemini 若有真实可用连接，独立提出方案/文案/交互意见并记录执行证据；本会话尚无 Gemini 直连，不得声称已咨询。GPT 对功能、误操作、动效、性能、无障碍做第二轮审查并列出遗留问题。
6. **上线**：PR + CI success 只证明工程候选。必须合并、Pages 实际部署、HTTP 200/资源哈希及浏览器回归成功才记录「已上线」。缺少真实设备、辅助技术或人工 PDF 质检不得签 Stage 6。

## 全面排查方法

运行 `python3 scripts/site_ux_audit.py`；依据唯一计划中的 33 个重点站点加上近期独立产品站，输出各仓库的 **源码级发现**。这是自动分诊，不是浏览器真机验收或质量绝对排名。按风险严重性、实际用户价值、可复现程度和修复成本排序，每轮 1–3 个能闭环上线的项目。
